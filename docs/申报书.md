**项目简介**

MoonBit 的数据库访问这层是空的。我在 mooncakes.io 上把数据库相关的包翻了一遍，有几个零散的绑定，但没有一个把「类型安全」和「查询构建」做起来。手写 SQL 有两个地方老出问题：字符串拼接留注入口子，列名或类型写错要到运行时才报。所以我把查询做成带类型的列 DSL——`Column[Int]` 只能跟 `Int` 比较，传 `String` 编译不过；所有值都转成 `?` 占位符加参数数组，没有插值的口子。后端通过 `Connection` trait 替换，内置零依赖的内存后端（wasm-gc 就能跑）和一个 SQLite 驱动（native）。从 `311a610` 起手到 `4313721`，一共 17 个 commit，都在 9 月 17 到 20 号之间。

**核心功能范围**

- `Select` / `Insert` / `Update` / `Delete` 四个构建器，渲染成 `Statement { sql, params }`，值永远走参数绑定。
- 条件 DSL：`eq / ne / gt / gte / lt / lte / like / in_ / is_null / is_not_null`，组合 `and_ / or_ / not_`，逃逸口 `Condition::raw`。
- 聚合 `count / sum / avg / min / max`，`group_by / having`，四种 JOIN（`join / left_join / right_join / full_join`），内存后端四种都真求值，缺侧填 null。
- 子查询：`IN`（`in_select`）、`EXISTS`（`Condition::exists`）、标量（`eq_sub` 到 `lte_sub`）、相关子查询（引用外层行，单层）。
- 两个后端走同一个 `Connection` trait：`Memory`（零依赖）+ `Sqlite`（vendor amalgamation，native）；事务走可选 `Transactional` trait。
- 测试 48 个 wasm-gc 用例 + 3 个 native 用例全绿，TDD 写的，渲染用例钉死 SQL 文本和参数顺序；`cmd/demo` 一条命令跑完整个功能面。

**限制与取舍**

- 相关子查询只支持单层，不追 grand-outer；一次一个 JOIN。
- 没有 Postgres 驱动，没有 migration / schema 管理。
- 代码量约 2000 行有效 MoonBit（另加约 900 行测试），低于大赛 4~10k 的参考区间——查询构建器本身是个聚焦的小库，这个体量是它该有的样子。
