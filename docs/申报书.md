# MoonORM 申报书

## 项目名称

MoonORM — 类型安全、参数化的 SQL 查询构建器

## 一句话

MoonBit 的 ORM：把 SQL 拼接换成带类型的列 DSL，值全部走参数绑定，后端通过
`Connection` trait 可替换，内置零依赖内存后端。

## 解决的问题

手写 SQL 字符串拼接有注入风险，且类型错误要到运行时才暴露。MoonORM 让查询
在编译期就带上列类型（`Column[Int]` 只能跟 `Int` 比较），所有值转成 `?`
占位符 + 参数数组，没有字符串插值注入的路径。

## 功能范围（功能完整性）

- 类型化列 DSL：`eq/ne/gt/gte/lt/lte/like/in_/is_null/is_not_null`，
  `and_/or_/not_/raw` 组合条件，`asc/desc` 排序，`set` 赋值。
- 四种构建器 `Select/Insert/Update/Delete`，渲染成 `Statement { sql, params }`。
- `Connection` trait：`select/insert/update/delete` 四个方法，SQL 驱动和内存
  后端共用同一套调用代码。
- `Memory` 后端：零依赖、wasm-gc 可跑，完整支持过滤/排序/分页/投影/CRUD。
- 可运行 demo：`moon run cmd/main` 走一遍建表→插入→查询→更新→删除。

## 工程质量

- 模块职责单一：DSL / 构建器 / 连接边界 / 后端 / 错误 分文件。
- 可替换边界：`Connection` trait 是唯一的后端抽象，换驱动不改调用方。
- 测试覆盖：21 个用例，覆盖 SQL 渲染、参数顺序、错误分支、内存 CRUD、黑盒消费。
- 错误处理：`OrmError` 用 `suberror`，区分标识符非法 / 查询非法 / 后端错误。
- 零警告：`moon check` 通过，无 deprecation、无 unused。

## 用户体验

- API 靠链式调用组织，读起来接近 SQL。
- 列带类型，IDE 能提示参数类型，写错类型编译期报错。
- 值是智能构造函数 `Value::int/text/...`，枚举变体包外只读这一 MoonBit 规则
  对用户透明。

## 复现步骤

```sh
moon test          # 21 个测试
moon run cmd/main  # demo
```

要求：MoonBit 工具链（0.1.20260915+），Node.js（跑 wasm-gc）。无其他依赖。
