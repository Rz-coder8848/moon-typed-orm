**基本信息**

- 项目名称：Moon-Typed-ORM —— 编译期类型安全、参数化的 SQL 查询构建器
- 参赛者：王仁政

- 是否为移植项目：否（原创）

**项目简介**

手写 SQL 一直有两个老毛病：字符串拼 SQL，用户输入直接拼进去就是注入；列名、类型写错，编译器一个字不吭，上线才报。MoonBit 的静态类型正好能治这个。所以我把查询做成带类型的列 DSL——`Column[Int]` 只能跟 `Int` 比，传 `String` 编译直接不过；所有值一律转 `?` 占位符 + 参数数组，值根本拼不进 SQL 字符串。

mooncakes.io 上数据库相关的包我翻过：`moonorm` 和它底下的 `moondb` 已经成熟，但那是运行时模型 + Session 的路子，编译期这层保护在 MoonBit 里现在还是空的，我补的就是这个位。我跟它走的不是一条路：它管模型和 Session，我管编译期把 SQL 拼对；它默认连真库，我内置一个零依赖内存后端，wasm-gc 就能跑，测试不用起库。技术上没走宏（MoonBit 宏生态还没起来），用 phantom type 把列类型带进 DSL——这条路 Diesel、Slick 在别的语言走过，MoonBit 里还没人做。

**核心功能范围**

- `Select` / `Insert` / `Update` / `Delete` 四个构建器，渲染成 `{ sql, params }`，值永远走参数绑定，不拼字符串。
- 条件 DSL：比较、`in_`、`is_null`、`and_` / `or_` / `not_`，不够用时可 `raw` 直接塞原始 SQL。
- 聚合 `count` / `sum` / `avg` / `min` / `max`，`group_by` / `having`，四种 JOIN（`join` / `left_join` / `right_join` / `full_join`），内存后端四种都真求值。
- 子查询：`IN`、`EXISTS`、标量比较，相关子查询支持单层。
- 两个后端走同一个 `Connection` trait：`Memory`（零依赖）+ `Sqlite`（native）；事务是可选 trait。
- 测试 48 个 wasm-gc 用例 + 3 个 native 用例全绿，`cmd/demo` 一条命令跑完整个功能面。
- 明确不做：Postgres 驱动、migration/schema 管理、多层相关子查询——先聚焦，摊大饼做不完。
