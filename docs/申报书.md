**基本信息**
- 项目名称：Moon-Typed-ORM —— 编译期类型安全、参数化的 SQL 查询构建器
- 参赛者：王仁政
- 联系方式：13068386886@163.com
- GitHub 仓库：https://github.com/Rz-coder8848/moon-typed-orm
- 项目方向：MoonBit 数据库访问层 / ORM 查询构建器
- 是否为移植项目：否

**项目目标与应用场景**
手写 SQL 有两个老毛病：字符串拼 SQL 会注入，列类型写错编译期不报错。本项目把查询做成带类型的列 DSL——`Column[Int]` 只能跟 `Int` 比，传 `String` 编译不过；值都是转 `?` 占位符 + 参数数组，进不了 SQL 字符串。
MoonBit 数据库栈的公认底座是 `moondb`（`Driver` / `Value` / `Row` 三个接口）；`moonorm` 在这个底座上做了模型 + Session 的运行时 ORM。本项目基于 moondb 扩展、不是重写 moonorm：在 `moondb` 接口之上加一层编译期类型安全的 DSL，再内置一个零依赖内存后端。moonorm 管运行时模型 + Session，本项目管编译期把 SQL 拼对；moonorm 默认连真库，本项目内置内存后端、测试不用起库。
应用场景：MoonBit 里任何要查库的代码用这套 DSL 写查询，编译期挡类型错、结构上挡注入，换数据库只换 driver。

**交付物说明**
- 核心库 `moon-typed-orm`：phantom type 列 DSL + 零依赖内存后端，wasm-gc 可跑。
- 适配包 `moon-typed-orm-moondb`：把同一套 DSL 接到 `moondb.Driver`，SQLite / Postgres / MySQL 换 driver 即可。
- 功能边界：单 JOIN、单层相关子查询；不做 migration、多驱动；`Condition::raw` 内存后端拒绝。
- 测试：48 个 wasm-gc + 3 个 native + 4 个 moondb 适配用例全绿；CI 跑 `check --target all` + `test wasm-gc` + `fmt --check`。规模约 2100 行有效代码 + 1000 行测试。
- 文档：README（三后端 + 用法示例）、`cmd/` 可跑 demo。

**技术路线说明**
1. 系统架构与模块划分：四层——类型层（`ast.mbt`，`Column[T]` phantom type）、构建层（`query.mbt`，渲染 `{ sql, params }`）、边界层（`conn.mbt`，`Connection` / `Transactional` trait）、后端层（`Memory` / `Sqlite` / moondb 适配包）。换后端只换 trait 实现，调用方代码不动。
2. 关键技术选型：phantom type 做编译期类型安全；`pub(open)` trait 解决跨包实现后端；零依赖内存后端保证 wasm-gc 可复现；vendor SQLite amalgamation 免除系统依赖。
3. 大模型与智能体工具的作用：查 MoonBit core 源码、写样板、对着编译报错修正。

**风险分析与应对方案**
1. 与 moonorm 被判功能重叠、生态竞争：定位写死基于 moondb 扩展、同基不同层；补它没有的编译期类型层 + 内置内存后端
2. phantom type 挡不住所有 SQL 语义错：明确不做 migration、多驱动、多层相关子查询
3. native 后端依赖 C 工具链或平台：核心库零依赖、wasm-gc 一条命令可复现；CI 以 Linux + wasm-gc 为准

**移植或参考说明**
- 本项目原创，无移植来源。
- 基于 `moonbitstack/moondb@0.1.8` 扩展：适配包 `moon-typed-orm-moondb` 实现 `moondb.Driver` 之上的一层，复用其 `Driver` / `Value` / `Row` / `DbError` 契约，不复制、不重写其实现。
- 许可证 Apache-2.0；引用的第三方代码是 SQLite amalgamation（`sqlite3.c`，public domain），用于 native 后端。
