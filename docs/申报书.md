- 项目名称：Moon-Typed-ORM —— 编译期类型安全、参数化的 SQL 查询构建器
- 参赛者：王仁政

**项目简介**

手写 SQL 有两个老毛病：字符串拼 SQL，用户输入一拼进去就是注入；列名类型写错，编译器不吭声，上线才炸。MoonBit 的静态类型正好治这个。所以我把查询做成带类型的列 DSL——`Column[Int]` 只能跟 `Int` 比，传 `String` 编译直接不过；所有值一律转 `?` 占位符 + 参数数组，值根本进不了 SQL 字符串。

MoonBit 的数据库栈已经有个公认的底座：`moondb`，就是那个 driver 接口（`Driver` / `Value` / `Row`，照搬 Go 的 database/sql 和 Python 的 DB-API 2.0）。`moonorm` 在这个底座上做了模型 + Session 的运行时 ORM。我做的事跟它不重叠，是往下补的一层：**在同一个 `moondb` 接口之上，加一层编译期类型安全的查询 DSL**，再内置一个零依赖的内存后端。

所以这个项目不是另起炉灶重写 moonorm，而是**基于 moondb 扩展**：扩展点就是把「编译期把 SQL 拼对」做成 moonorm 里没有的东西。落地是两块——

- 核心库 `moon-typed-orm`：带 phantom type 的列 DSL + 零依赖内存后端，不依赖任何第三方库，wasm-gc 就能跑；
- 独立适配包 `moon-typed-orm-moondb`：把同一套 DSL 接到 `moondb.Driver` 上，SQLite、Postgres、MySQL 换 driver 就行，查询代码一行不用改。

跟 moonorm 的关系一句话：它管「运行时模型 + Session」，我管「编译期把 SQL 拼对」；它默认连真库，我内置内存后端、测试不用起库。底层是同一个 moondb 底座，所以是扩展，不是重复。

**核心功能范围**

- `Select` / `Insert` / `Update` / `Delete` 四个构建器，渲染成 `{ sql, params }`，值永远走参数绑定，不拼字符串。
- 条件 DSL：比较、`in_`、`is_null`、`and_` / `or_` / `not_`，不够用时可 `raw` 直接塞原始 SQL。
- 聚合 `count` / `sum` / `avg` / `min` / `max`，`group_by` / `having`，四种 JOIN（`join` / `left_join` / `right_join` / `full_join`），内存后端四种都真求值。
- 子查询：`IN`、`EXISTS`、标量比较，相关子查询支持单层。
- 三个后端走同一个 `Connection` trait：`Memory`、`Sqlite`，外加基于 moondb 接口的适配包；事务是可选 trait。
- 测试 48 个 wasm-gc 用例 + 3 个 native 用例 + 4 个 moondb 适配用例全绿，`cmd/demo` 一条命令跑完整个功能面。
- 明确不做：Postgres/MySQL 驱动本身、migration/schema 管理、多层相关子查询。查询构建器就应该是个聚焦的小库，现在 2100 行有效代码 + 1000 行测试。

**移植或参考说明**

- 本项目原创，无移植来源。
- **基于 `moonbitstack/moondb@0.1.8` 扩展**：适配包 `moon-typed-orm-moondb` 实现 `moondb.Driver` 之上的一层，复用其 `Driver` / `Value` / `Row` / `DbError` 契约，不复制、不重写其实现。
- 与 `moonbitstack/moonorm` 的关系：同基不同层——都基于 moondb 底座，但 moonorm 做运行时模型 + Session，本项目做编译期类型安全 DSL + 零依赖内存后端。本项目不依赖 moonorm，也不重复它的模型/Session 层。
- 本项目许可证：Apache-2.0。
- 唯一引用的第三方代码是 SQLite 的 amalgamation（`sqlite3.c`，public domain），用于 native 后端。
